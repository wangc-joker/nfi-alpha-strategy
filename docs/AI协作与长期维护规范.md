# AI 协作与长期维护规范

这份文档是给未来的开发者和 AI 助手看的。它的作用是让这个工程在长期迭代中保持同一套开发方向。

## 1. 项目总目标

构建一套参考 NostalgiaForInfinity 优点、但结构更清晰的高级 Freqtrade 策略。

目标：

- 高收益。
- 低回撤。
- 可解释。
- 可维护。
- 可插拔。
- 支持未来接入 FreqAI。

非目标：

- 不追求 100% 胜率。
- 不复制 NFI 的巨型单文件结构。
- 不用无限补仓掩盖错误入场。
- 不把实盘状态和研发代码混在一起。

## 2. 每次接手先读

每个新 AI 或新开发环境接手时，先读：

1. `README.md`
2. `docs/工程设计总纲.md`
3. 当前最近的 `research` 实验记录
4. 最近一次回测报告

不要一上来重构，也不要直接改核心策略。

## 3. 开发原则

- 主流程稳定，信号插件化。
- 新信号必须独立模块化。
- 每个信号必须有 tag。
- 每个信号必须能单独开关。
- 每个信号必须写明市场假设。
- 每个策略版本必须能复现回测。

## 4. 新增信号的要求

新增信号前，先写一份研究说明：

```text
信号名称：
市场假设：
适合行情：
不适合行情：
使用指标：
入场条件：
退出配合：
风险点：
预期改善：
回测区间：
```

新增信号后，必须：

- 单独跑回测。
- 和基线策略对比。
- 记录收益、回撤、交易数、持仓时间。
- 如果表现不稳定，默认关闭。

## 5. FreqAI 接入原则

FreqAI 后期可以研究，但不能一开始主导交易。

建议角色：

- 预测未来波动风险。
- 预测趋势延续概率。
- 给候选入场评分。
- 帮助过滤低质量信号。

禁止角色：

- 直接让 AI 单独决定买卖。
- AI 结果不可解释还直接进实盘。
- 没有对照实验就认为 AI 提升有效。

## 6. 回测纪律

每次重要改动至少测试：

- 最近半年。
- 最近一年。
- 包含下跌行情的一段区间。
- 固定 top9。
- 固定 top20/top30。

观察指标：

- 总收益。
- 最大回撤。
- 交易数。
- 胜率。
- 平均持仓时间。
- 未平仓数量。
- 最差单笔亏损。
- 资金占用。

## 7. 实盘纪律

进入实盘前必须经过：

```text
代码能加载
  -> 回测通过
  -> 多区间回测稳定
  -> dry-run 运行
  -> 小资金实盘
```

实盘中避免：

- 有持仓时频繁 reload。
- 修改策略后不回测直接上线。
- 让币池更新脚本影响持仓状态。
- 忽略交易所最小下单额。

## 8. 文档纪律

每次完成一个阶段，更新对应文档：

- 设计变化写入 `docs`。
- 实验结论写入 `research`。
- 配置变化写入 `configs` 或说明文件。
- 实盘问题写入复盘记录。

## 9. 版本命名建议

策略版本：

```text
AlphaRegimeStrategy_v0_1
AlphaRegimeStrategy_v0_2
AlphaRegimeStrategy_v1_0
```

信号版本：

```text
trend_pullback_v1
mean_reversion_v1
breakout_follow_v1
```

配置版本：

```text
config.backtest.alpha.top9.300u.json
config.backtest.alpha.top30.500u.json
config.dryrun.alpha.top30.300u.json
```

## 10. 判断一个改动是否值得保留

一个改动要保留，至少满足其中两项：

- 提高收益且回撤没有明显变差。
- 降低回撤且收益没有明显变差。
- 减少长时间被套。
- 提高信号可解释性。
- 提高实盘稳定性。
- 提高代码可维护性。

如果只在一个很短区间提升收益，但其他区间变差，默认不合并到主流程。
