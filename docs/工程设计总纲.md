# NFI Alpha Strategy 工程设计总纲

## 0. 项目愿景

这个工程的目标是构建一套可以长期迭代的 Freqtrade 高级策略体系。

路线已经调整为：

```text
先以 NostalgiaForInfinityX7 为参考实现进行模块化重构；
第一目标是尽量对齐原版 NFI 回测结果；
第二目标是在保持结果接近的前提下拆分结构；
第三目标是在重构版基础上调优；
第四目标是未来接入 FreqAI。
```

旧的从零构建 `AlphaRegimeStrategy` 路线保留为实验沙盒，不再作为主线。

我们追求的是：

- 高收益，但不依赖表面上的 100% 胜率。
- 低回撤，比单纯高胜率更重要。
- 可维护，比巨型单文件更重要。
- 可解释，方便你作为 Java 开发者持续学习和改造。
- 可插拔，未来发现新的好信号时，可以接入，而不是侵入主流程。
- 可演进，后期可以接入 FreqAI，但不让 AI 一开始污染基础策略架构。

## 1. 工程放在哪里

```text

nfi-alpha-strategy         新策略研发主工程
```

## 2. 长期协作原则

这个项目会长期迭代，所以必须让未来的你、其他电脑、其他 AI 都能理解“我们为什么这么写”。

核心原则：

- 每一次重要策略变更，都要有 `research` 或 `docs` 记录。
- 每一个新信号都要说明：市场假设、入场条件、退出配合、适用币种、风险点。
- 回测结果不能只看收益，要同时记录回撤、持仓时长、未平仓、交易数、资金占用。
- 主流程保持稳定，实验信号以插件方式接入。
- 实盘配置和研发配置分离，研发工程不直接承载实盘状态。

## 3. 从 NFI 借鉴什么

NFI 值得参考的部分：

- 多周期数据：5m 入场，高周期过滤趋势。
- 币种池分层：不是所有币都用同一种策略。
- tag 系统：每个入场信号留下来源，方便后续出场和复盘。
- 自定义出场：不是依赖简单 ROI 表。
- 运行期保护：滑点、持仓限制、模式限制。
- 动态币池：根据市场状态调整候选币。
- 利润追踪思想：不急着卖，尝试捕捉更好退出点。

需要避免的部分：

- 巨型单文件。
- 过多硬编码 if 条件堆叠。
- 运行时缓存不持久化导致 reload 后行为变化。
- 过度依赖补仓拉高胜率。
- 很难解释的复杂仓位状态机。

新的执行策略：

```text
不再靠猜测吸收 NFI；
而是先把 NFI 重构成模块化版本；
每一步都和原版 NFI 回测结果对齐；
之后再做我们自己的改造。
```

## 4. 新策略核心思想

实验策略名：

```text
AlphaRegimeStrategy
```

主线重构策略名：

```text
NFIRefactorStrategy
```

`AlphaRegimeStrategy` 的定位调整为：

```text
实验沙盒；
新模块验证；
新信号快速试验；
```

`NFIRefactorStrategy` 的定位是：

```text
承接 NFI 行为；
逐步模块化；
未来调优和实盘候选；
```

核心不是“超跌就买”，而是：

```text
市场状态判断
  -> 币种质量筛选
  -> 多信号插件评分
  -> 风险预算决定仓位
  -> 分层退出和回撤保护
```

策略应能回答：

- 当前市场适合开多吗？
- 哪些币当前更值得交易？
- 这个入场信号属于趋势回调、均值回归、突破延续，还是特殊事件？
- 这笔交易允许多大风险？
- 如果走势不符合预期，多久退出？
- 如果盈利，怎么止盈而不是过早卖飞？

## 5. 推荐架构

未来策略文件不应该变成另一个 7 万行文件。推荐拆成这些模块：

```text
strategies/
  AlphaRegimeStrategy.py
  alpha_modules/
    coin_universe.py
    market_regime.py
    signal_base.py
    signals/
      trend_pullback.py
      mean_reversion.py
      volatility_squeeze.py
      breakout_follow.py
    risk_manager.py
    exit_manager.py
    position_sizer.py
    state_store.py
```

模块职责：

- `coin_universe`：币种池、成交量筛选、黑名单、白名单。
- `market_regime`：判断 BTC/ETH/整体市场状态。
- `signal_base`：定义信号插件接口。
- `signals`：每个入场逻辑单独一个模块。
- `risk_manager`：是否允许交易、最大回撤保护、波动率过滤。
- `position_sizer`：每单仓位、风险预算、最大持仓数。
- `exit_manager`：止盈、止损、时间退出、趋势破坏退出。
- `state_store`：持久化运行状态，避免 reload 后丢失关键记忆。

## 6. 可插拔信号设计

每个入场信号必须像插件一样接入主流程。

建议接口：

```python
class SignalModule:
    name = "trend_pullback"
    version = "1.0"

    def add_indicators(self, dataframe, metadata):
        return dataframe

    def generate_entry(self, dataframe, metadata):
        return dataframe

    def explain(self):
        return {
            "idea": "...",
            "market": "...",
            "risk": "..."
        }
```

主策略只做编排：

```text
加载信号模块
  -> 每个模块添加自己的指标
  -> 每个模块输出 entry_score / entry_tag
  -> 主流程统一做风险过滤
  -> 统一写 enter_long / enter_tag
```

这样未来发现一个好信号，只需要新增一个模块，而不是改主策略核心。

## 7. 风险控制目标

这个项目不追求虚假的 100% 胜率。目标更实际：

- 回撤优先控制。
- 单笔亏损可解释。
- 不靠无限补仓修复错误入场。
- 允许小亏出局。
- 尽量减少长时间深套。
- 资金使用率可控。

阶段性指标目标：

```text
第一阶段：可运行、可回测、结构清晰
第二阶段：收益超过普通买入持有，回撤可控
第三阶段：收益接近或超过 NFI 某些配置，回撤更低
第四阶段：长期多周期回测稳定
第五阶段：模拟盘运行稳定
第六阶段：小资金实盘验证
```

## 8. 阶段路线图

当前主线阶段以 [NFI重构与改造路线图](D:\test\nfi-alpha-strategy\docs\NFI重构与改造路线图.md) 为准。

下面旧阶段路线保留为 Alpha 实验沙盒记录，不再作为主开发路线。

### 阶段 1：工程骨架

目标：

- 建立独立工程目录。
- 建立文档和协作规范。
- 建立基础策略文件骨架。
- 建立配置模板和回测脚本。

完成标准：

- 能在 Freqtrade 中加载空策略。
- 能跑一次无交易或少量交易回测。
- 目录结构清楚。

### 阶段 2：基础市场状态

目标：

- 加入 BTC/ETH 市场状态判断。
- 区分上涨、震荡、下跌、高波动。
- 在不适合交易时减少或禁止开仓。

参考 NFI：

- 借鉴多周期过滤思想。
- 不直接复制 NFI 的大量固定阈值。

完成标准：

- 回测报告能显示不同市场状态下的交易表现。

### 阶段 3：动态币池

目标：

- 从主流币池中按当前成交量、波动率、趋势质量筛选。
- 支持固定币池和动态币池两种模式。
- 保留 pairlist 生成报告。

完成标准：

- 每次币池变化可追踪。
- 币池变化不会无意义触发实盘 reload。

### 阶段 4：第一组入场插件

目标：

- 实现趋势回调信号。
- 实现均值回归信号。
- 实现波动率收缩后突破信号。

完成标准：

- 每个信号有独立 tag。
- 每个信号有独立回测统计。
- 可以单独开关。

### 阶段 5：退出系统

目标：

- 分批止盈。
- 趋势破坏退出。
- 时间止损。
- 波动率止损。
- 利润追踪状态持久化。

参考 NFI：

- 借鉴利润追踪思想。
- 改成可持久化，避免 reload 丢失。

完成标准：

- 每种退出原因都有明确 tag。
- reload 后关键退出状态能恢复。

### 阶段 6：仓位管理

目标：

- 不先做复杂 grind。
- 先做风险预算仓位。
- 后续只允许轻量补仓。
- 补仓必须有次数、资金、回撤上限。

完成标准：

- 小资金也能跑，不因为补仓路径过深失真。
- 回测和实盘资金行为接近。

### 阶段 7：回测评估体系

目标：

- 固定 top9/top20/top30 测试集。
- 固定牛市、熊市、震荡市测试区间。
- 自动生成收益、回撤、交易数、持仓时长、未平仓报告。

完成标准：

- 每次策略变更可以对比前后结果。
- 不凭单次高收益决定策略好坏。

### 阶段 8：模拟盘

目标：

- dry-run 运行至少 2-4 周。
- 记录信号命中、错过、退出质量。
- 检查 reload、缓存、币池更新、网络异常。

完成标准：

- 没有明显异常行为。
- 实盘脚本和监控脚本稳定。

### 阶段 9：小资金实盘

目标：

- 小资金验证执行质量。
- 检查滑点、手续费、最小下单额。
- 验证策略状态持久化。

完成标准：

- 实盘行为能解释。
- 和 dry-run 差异可接受。

### 阶段 10：FreqAI 接入

目标：

- FreqAI 不直接决定买卖。
- 先作为辅助评分器。
- 预测未来波动、趋势概率、回撤风险。

建议接入方式：

```text
传统信号先给出候选
  -> FreqAI 给质量评分
  -> 风险模块决定是否允许入场
```

完成标准：

- AI 模块可开关。
- 关闭 AI 后基础策略仍能独立运行。
- AI 提升经过回测和模拟盘验证。

## 9. 成功标准

长期目标不是“某一次回测爆炸收益”，而是：

- 多年份、多币种表现稳定。
- 回撤明显低于激进补仓策略。
- 收益高于保守趋势策略。
- 每笔交易都有可解释原因。
- 策略可以被维护，而不是只能被敬畏。
