# 0007 候选信号评分

## 目标

阶段 6 解决了“同一交易对同一根 K 线多个信号谁优先”的问题，但还没有解决全市场候选之间如何排序。

阶段 7 先做评分字段：

```text
alpha_entry_score
```

每个信号模块负责生成自己的分数：

```text
signal_trend_pullback_score
signal_breakout_retest_score
```

主策略选择信号时，把被选中的信号分数写入：

```text
alpha_entry_score
```

## 当前原则

先观测，后过滤。

短周期实验后曾临时采用：

```text
trend_pullback.min_score = 50
breakout_retest.min_score = 0
```

`trend_pullback` 第一轮小样本验证显示，50 分是轻微过滤，能筛掉少量劣质交易；60 和 70 分会过滤过度。

但 3 个月验证后发现，50 分并不稳健。因此当前主线退回：

```text
trend_pullback.min_score = 0
breakout_retest.min_score = 0
```

## trend_pullback 评分

基础分：

```text
20
```

加分项：

```text
回调深度处于 0.6% 到 2.2%：+20
RSI14 处于 42 到 54：+15
RSI7 小于 38：+10
当前成交量高于 30 根均量：+15
趋势质量分 >= 5：+10
趋势质量分 >= 6：+10
```

理论最高分：

```text
100
```

## breakout_retest 评分

当前 `breakout_retest` 仍然没有接入主线，但它也实现同样评分接口，方便以后继续测试。

## 限制

Freqtrade 的 `populate_entry_trend` 是按交易对分别计算的，不天然支持“这一轮全市场所有候选先排序，再只选择最高的几个”。

所以 `alpha_entry_score` 是全市场资金调度的前置条件，不是完整资金调度器。

## 下一步

可以做两类实验：

```text
1. 单信号分数阈值实验：
   例如 trend_pullback.min_score = 50 / 60 / 70。

2. 全市场候选导出：
   把每轮候选信号导出成表，离线分析高分交易和低分交易的收益差异。
```

## 结论

短周期下，50 分看起来略优：

```text
trend_pullback.min_score = 50
```

它只过滤掉 1 笔交易，收益和回撤都有轻微改善。

但这只是短区间小样本结果，不能视为最终参数。

## 三个月验证

Top30、300U、`max_open_trades = 2`，区间：

```text
2026-01-15 到 2026-04-15
市场变化：-36.52%
```

阈值 0：

```text
交易数：430
收益：-57.920 USDT
收益率：-19.31%
胜率：17.2%
最大回撤：20.39%
Profit factor：0.74
```

阈值 50：

```text
交易数：419
收益：-59.236 USDT
收益率：-19.75%
胜率：16.7%
最大回撤：21.50%
Profit factor：0.73
```

## 三个月结论

`min_score = 50` 没有通过稳健性验证。

它在 9 天样本中略好，但在 3 个月下跌市场中收益更差、回撤更大，所以不能作为主线参数。当前主线恢复：

```text
trend_pullback.min_score = 0
```

更重要的结论：

当前策略虽然在 3 个月下跌市场中跑赢市场本身，但仍然出现接近 20% 的账户回撤。这说明问题不在单笔入场评分，而在市场状态过滤仍然不够严格。

下一步应该优先研究：

```text
BTC 熊市/高压状态下减少交易或暂停交易
```
