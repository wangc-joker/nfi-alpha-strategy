# 0003 动态主币池 Top30

## 目标

建立 Alpha 策略自己的动态币池流程。

这一步不是策略信号优化，而是把交易对象管理独立出来，避免每次手工改配置。

## 设计

主币池文件：

```text
configs/main_coins.nfi_top_coins.json
```

生成脚本：

```text
scripts/update_alpha_dynamic_top30.ps1
```

选择逻辑：

```text
读取主币池
  -> 请求 Binance Futures exchangeInfo
  -> 请求 Binance Futures 24h ticker
  -> 只保留 USDT PERPETUAL 且在主币池中的币
  -> 按 currentQuoteVolume24h 降序排序
  -> 取前 30 个
```

## 为什么先用 24h 当前成交量

30 天均量需要逐币请求日线，容易触发 Binance IP 限频。当前阶段我们先用请求次数更少、稳定性更高的 24h quote volume。等策略核心稳定后，再研究缓存化的 30 天均量版本。

## 和 NFI 的关系

初始主币池沿用 NFI `top_coins_mode_coins` 的集合。后续 Alpha 策略会独立维护这个列表，不再强依赖 NFI 源码。

## 2026-04-25 Top30 烟测

测试命令：

```powershell
docker compose run --rm freqtrade backtesting --config /freqtrade/user_data/config.backtest.alpha.top30.300u.json --strategy-path /freqtrade/user_data/strategies --strategy AlphaRegimeStrategy --timerange 20260401-20260410 --timeframe 5m
```

结果摘要：

```text
交易数：47
收益：+8.172 USDT
收益率：+2.72%
胜率：25.5%
最大回撤：2.77%
最终资金：308.172 USDT
最佳交易对：CRV/USDT:USDT +3.17%
最差交易对：NEAR/USDT:USDT -1.74%
```

注意：

本地数据缺少 `WLD/USDT:USDT` 的 5m/funding/mark 数据，Freqtrade 回测时给出 warning 并跳过。后续动态币池脚本可以增加本地数据可用性过滤，避免回测配置包含缺数据币种。

阶段结论：

扩大到 top30 后，第一版趋势回调信号在短区间内能盈利，但胜率较低，亏损交易数量多。下一步重点应该是提高信号质量和退出质量，而不是增加交易频率。
