# 0006 信号优先级与资金占用

## 背景

阶段 5 测试 `breakout_retest` 后发现一个重要问题：

```text
新增信号本身亏损不大，但它会抢占 max_open_trades = 2 的仓位。
```

这会导致原本更好的 `trend_pullback` 交易无法进入，从而让总收益下降。

## 第一版方案

给每个信号模块增加统一字段：

```text
priority
```

数值越大，优先级越高。

当前定义：

```text
trend_pullback.priority = 100
breakout_retest.priority = 80
```

其中 `breakout_retest` 仍然只是研究备选模块，没有接入主策略。

## 主流程变化

入场阶段新增字段：

```text
alpha_entry_priority
```

主策略遍历所有已启用信号模块时，不再把多个标签拼接到一起，而是：

```text
如果当前信号触发，并且通过 alpha_allow_long；
如果当前信号 priority 大于这一行已有的 alpha_entry_priority；
则用当前信号覆盖 enter_tag，并更新 alpha_entry_priority。
```

这样同一根 K 线、同一个交易对上，如果多个信号同时触发，只会留下最高优先级的那个。

## 这解决了什么

解决：

```text
同一行多信号标签混乱
低优先级信号覆盖高优先级信号
后续无法统计信号贡献
```

没有完全解决：

```text
不同交易对之间仍然会争夺 max_open_trades
Freqtrade 本身不会按我们的 priority 对全市场候选交易排序
```

所以这只是第一层“信号内优先级”，不是完整的“全市场资金调度器”。

## 后续方向

如果要真正解决资金占用，需要继续做第二层：

```text
信号资金桶：
给 trend_pullback 固定保留一部分 max_open_trades
给突破类信号单独限制最大同时持仓
```

或第三层：

```text
全市场信号评分：
同一轮所有候选币种先打分
只允许分数最高的一批发出 enter_long
```

第三层会更接近真正的组合管理，但实现复杂度也更高，需要谨慎推进。
